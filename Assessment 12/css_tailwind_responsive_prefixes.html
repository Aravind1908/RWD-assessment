Tailwind CSS: Responsive Prefixes (sm:, md:, lg:, xl:, 2xl:)

How Tailwind does responsive design mobile-first — no media queries written, just md: and lg: in front of any utility — demonstrated with a card grid and a navbar.

CSS Framework · Tailwind · Responsive

1Introduction

In hand-written CSS, responsive design means writing @media blocks. In Tailwind, the same idea is built into the class names: responsive prefixes — sm:, md:, lg:, xl:, 2xl: — go in front of any utility and mean "from this screen width upward, use this value instead".

The system is mobile-first by construction: the class without a prefix is what phones see, and each prefix layers an upgrade on top for wider screens. There is no "mobile prefix" to write — you simply don't prefix the base version. 

<!-- phones: stacked column; from md: (768px) up: a row -->
<div class="flex flex-col md:flex-row">…</div>

/* What Tailwind actually generates behind the scenes: */
.flex-col { flex-direction: column; }
@media (min-width: 768px) {
  .md\:flex-row { flex-direction: row; }
}

You never write the media query — the prefix is the media query. The rest of this page covers the five breakpoints, how they layer, and a real card grid built from them.

2Syntax and its Explanation

The five default breakpoints

PrefixApplies atTypical device
(none)every width — the mobile basephones
sm:min-width: 640pxlandscape phones
md:min-width: 768pxtablets in portrait
lg:min-width: 1024pxtablets in landscape / small laptops
xl:min-width: 1280pxdesktops
2xl:min-width: 1536pxlarge desktops

Each prefixed class generates a min-width media query around that one utility — so grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 is three utilities, two of them wrapped in media queries.

How mobile-first layering works

<div class="p-4 md:p-6 lg:p-8 gap-4 lg:gap-8">
  /* below 768px  → p-4,  gap-4   (the base) */
  /* 768px and up → p-6  overrides p-4; gap-4 still applies */
  /* 1024px and up → p-8 and gap-8 override everything below */
</div>

Every breakpoint only overrides the classes it names — everything else stays as-is from the base. That's why mobile-first works with so little code: the phone layout is the default, and each larger screen sends a short list of upgrades.

Prefixes combine with state variants

<button class="bg-blue-600 hover:bg-blue-700 md:hover:bg-blue-800">
  /* any hover      → blue-700 */
  /* hover AND md+  → blue-800 (both conditions must hold) */
</button>

Order convention: breakpoint:state:utility. A prefix can go in front of anything — colors, spacing, type, layout: text-2xl lg:text-4xl, hidden md:block, max-w-md xl:max-w-4xl.

Key rule: There is no "below md" prefix in the normal flow — that's what mobile-first means. For the rare exception ("this only on small screens"), Tailwind provides max-md: and friends (max-lg:grid-cols-1), which generate max-width queries. Use them sparingly; the upward flow is the system's grain.

The breakpoints are defaults, not laws. In v4 you retune them in CSS — @theme { --breakpoint-md: 48rem; } — and in v3 in tailwind.config.js under theme.screens. Whatever the numbers, the working method is the same: pick breakpoints where your content breaks, not by device name.

4Example Programs with Explanation

Example 1 — Mobile-first card grid

Six cards that sit in 1 column on phones, 2 columns from sm:, and 3 columns from lg:. Save as index.html (needs internet for the CDN).

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Mobile-First Card Grid</title>
  <script src="https://cdn.tailwindcss.com"></script>
</head>
<body class="bg-gray-50 p-6 text-gray-900">
  <div class="max-w-5xl mx-auto">
    <h1 class="text-2xl font-bold">Card grid: 1 → 2 → 3 columns</h1>
    <p class="text-sm text-gray-500">
      Resize the window: base = mobile, sm: from 640px, lg: from 1024px.
    </p>

    <!-- the whole responsive behavior is this one class list -->
    <div class="mt-6 grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-4">
      <div class="bg-white rounded-xl border border-gray-200 p-5">
        <h2 class="font-semibold">Design</h2>
        <p class="mt-1 text-sm text-gray-500">Layouts that adapt to any screen.</p>
      </div>
      <div class="bg-white rounded-xl border border-gray-200 p-5">
        <h2 class="font-semibold">Develop</h2>
        <p class="mt-1 text-sm text-gray-500">Composed from utility classes.</p>
      </div>
      <div class="bg-white rounded-xl border border-gray-200 p-5">
        <h2 class="font-semibold">Deploy</h2>
        <p class="mt-1 text-sm text-gray-500">Purged, tiny production CSS.</p>
      </div>
      <!-- …repeat the same three card blocks once more (6 cards total) -->
    </div>
  </div>
</body>
</html>
Explanation of Example 1:
  • The entire responsive behavior is one class list: grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 — no media query typed anywhere.
  • Phones get grid-cols-1 (the base). From 640px, sm:grid-cols-2 takes over. From 1024px, lg:grid-cols-3 takes over.
  • gap-4 is unprefixed on purpose — the same 16px gap works at every width, so it needs no prefixes at all.
  • Each card is identical: white, gray-200 border, p-5, a bold title and a muted line — the standard card vocabulary from the color guide.
How to run
Save as index.html and open in a browser with internet. Resize across 640px and 1024px and watch the columns change. Try md:grid-cols-2 instead of sm: and notice the 2-column range shift.

Example 2 — Responsive navbar

One navbar that stacks vertically on phones and becomes a horizontal bar from sm: — plus a headline that steps up with the screen. Prefixes on layout, gaps, and type, all in one page.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Responsive Navbar</title>
  <script src="https://cdn.tailwindcss.com"></script>
</head>
<body class="bg-white">
  <!-- stacked column on phones, row from sm: -->
  <nav class="max-w-5xl mx-auto px-4 sm:px-6 py-4 flex flex-col
              sm:flex-row items-center justify-between gap-3 sm:gap-6">
    <span class="text-lg font-bold text-blue-600">acme.</span>
    <div class="flex flex-col sm:flex-row items-center
                gap-3 sm:gap-6 text-sm font-medium">
      <a href="#" class="text-gray-600 hover:text-blue-600">Features</a>
      <a href="#" class="text-gray-600 hover:text-blue-600">Pricing</a>
      <a href="#" class="bg-blue-600 hover:bg-blue-700 text-white px-4
                  py-2 rounded-lg transition">Sign up</a>
    </div>
  </nav>

  <!-- the headline steps up with the screen -->
  <main class="max-w-5xl mx-auto px-4 sm:px-6 py-16">
    <h1 class="text-3xl sm:text-4xl font-bold tracking-tight">
      Stacked on phones, in a row from sm: (640px)
    </h1>
    <p class="mt-4 text-gray-600 sm:text-lg max-w-xl">
      One navbar, two layouts — only the sm: prefixes differ.
    </p>
  </main>
</body>
</html>
Explanation of Example 2:
  • The nav is flex flex-col sm:flex-row — the same "stacked → row" move as the card grid, applied to navigation.
  • px-4 sm:px-6 and gap-3 sm:gap-6 show that spacing scales up too: tighter gutters and gaps on phones, roomier on tablets+.
  • text-3xl sm:text-4xl demonstrates responsive type — headlines usually get one step bigger with the viewport.
  • Everything below 640px comes from the unprefixed classes; above it, the sm: set overrides — a perfect mobile-first layering in a ~30-line page.
How to run
Save as index.html and open in a browser with internet. Resize across 640px: the nav flips from column to row, the gutters widen, and the headline grows. Swap sm:flex-row for md:flex-row to push the switch to tablet width.

5Advantages

  • Zero media queries to write: one prefix does what a whole @media block does — less CSS to write, name, and maintain.
  • Mobile-first by default: the unprefixed class is the mobile style, so small screens get the lightest possible markup and behavior.
  • Composable at the class level: any utility accepts any prefix (md:grid-cols-2, lg:text-5xl, xl:max-w-4xl), and prefixes stack with state variants (md:hover:bg-blue-800).
  • Consistent breakpoints project-wide: everyone on the team uses the same 640/768/1024/1280/1536 grid (or your custom set), so layouts shift at the same widths everywhere.
  • Visible in the markup: the responsive behavior is right there in the class list — no need to open a stylesheet and hunt for which media query owns which rule.
  • Easy to tune: breakpoints are theme values — change --breakpoint-md (v4) once and every md: class in the project follows.

6Conclusion

Tailwind's responsive prefixes — sm: (640px), md: (768px), lg: (1024px), xl: (1280px), 2xl: (1536px) — turn responsive design into a class-name problem: write the mobile layout unprefixed, then layer min-width upgrades in front of the specific utilities that change. grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 is a full responsive card grid in five words, with no media query written by hand.

The habits: base = mobile, prefixes go upward, and every breakpoint should exist because your content needed it — not because a device has a name. Combined with the state variants in the companion document css_tailwind_state_variants.html, prefixes and states cover virtually every "when should this look different?" question a UI has.
