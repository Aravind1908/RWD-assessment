Deploying on Vercel

GitHub import in a few clicks, a preview URL for every pull request, and custom domains with automatic HTTPS — plus a short Netlify comparison.

Hosting · Vercel · Deployment

1Introduction

Vercel is the platform from the Next.js team: Git-driven deploys served from a global edge network, with automatic framework detection. Its signature feature: every branch and pull request gets its own live preview URL. Static sites deploy with zero config; server-side code (serverless/edge functions) deploys right next to them.

2Deployment, Step by Step

GitHub import

  1. Sign in at vercel.com with GitHub → Add New… → Project → pick the repo.
  2. Review the auto-detected framework preset (Next.js, Vite, React, static…) — for a plain HTML folder it's "no build, publish as-is".
  3. Add environment variables if needed → Deploy. Live at https://<project>-<you>.vercel.app; every future push redeploys automatically.

CLI equivalent: npx vercel (preview) and npx vercel --prod (production) — for folders or non-GitHub remotes.

Preview deployments

Every push to a non-main branch — and every PR — builds a unique, shareable URL: a fully working copy of that exact commit, isolated from production. Vercel auto-comments the URL on the GitHub PR, so reviewers test the real artifact. After merge, production updates; previews can be discarded. The link in the PR is the deploy.

Custom domains

  1. Project → Settings → Domains → Add → type yourdomain.com.
  2. Create the exact DNS records Vercel shows (below) at your registrar.
  3. Vercel verifies (usually minutes) and issues the HTTPS certificate automatically, free.
DNS + SSL, the short version.
  • Records (the dashboard always shows exact values): root domain → A record — on Vercel, @ → 76.76.21.21; www/subdomains → CNAME — on Vercel, www → cname.vercel-dns.com. Netlify's shape is the same idea: CNAME root and www to <site>.netlify.app.
  • Verification: the platform polls public DNS after you save; propagation is usually seconds-to-minutes (48h is the theoretical max, never seen in practice).
  • HTTPS/SSL: both platforms provision and renew TLS certificates automatically once DNS is correct — no cert files, no renewal dates. You only toggle redirect HTTP → HTTPS (on) / force SSL.

4Example

Deploy the demo_site/ folder (one-file static site, shared with the Netlify guide) via CLI — the same flow the UI import runs for you:

# inside demo_site/ (free Vercel account required)
npx vercel login            # browser sign-in, one time
npx vercel                  # detects static site → preview URL (*.vercel.app)
npx vercel --prod           # promote to the production URL
npx vercel domains add yourdomain.com   # after creating the DNS records
Requirements
Free Vercel account, Node for the CLI, internet. Through the UI instead (Add New → Project → repo), every future push redeploys and each PR gets its preview URL + GitHub comment.

5Advantages

  • Import-to-live in clicks — framework auto-detection means zero build config; the URL arrives while you're reading the confirmation.
  • Previews change review culture — every PR has a working link; "works on my machine" stops being an argument.
  • Domains are frictionless — paste the suggested records, wait minutes, HTTPS appears and renews on its own.

6Conclusion

Vercel's flow: sign in with GitHub → import the repo → framework auto-detected → Deploy — production follows the default branch, every PR gets a live preview URL commented on automatically, and a custom domain is two DNS records away with HTTPS free. Versus Netlify: near-tie for static sites; Vercel wins for Next.js, Netlify for quick publishes and built-in forms. The domain rule is the same everywhere: root → A record, www → CNAME, then the certificate takes care of itself.
