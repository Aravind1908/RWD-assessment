Deploying on Netlify

Two ways: drag-and-drop (live in under a minute, no repo needed) and Git-based continuous deployment (every push redeploys automatically).

Hosting · Netlify · Deployment

1Introduction

Netlify is a static-first host: give it files (or a repo it can build into files) and it serves them from a global CDN with HTTPS included. Two doors in — Drop for a folder of finished files (prototypes, one-shots), Git integration for anything you'll keep updating. Both end at a live https://<site>.netlify.app.

2The Two Methods, Step by Step

Method 1 — Drag-and-drop (Netlify Drop)

  1. Prepare a folder with index.html at its root. Frameworks: run npm run build first and drag the output folder (dist/), not the source.
  2. Open app.netlify.com/drop (sign in takes 30 seconds).
  3. Drag the folder in and let it upload.
  4. It's live at https://random-name.netlify.app. Optionally rename it under Site settings → Change site name.

Updating = drag again (or use the CLI). Each upload is a new, saved deploy.

Method 2 — Git-based continuous deployment

  1. Push your source to GitHub/GitLab.
  2. Netlify: Add new site → Import an existing project → pick the repo.
  3. Set build command (npm run build; empty for plain static) and publish directory (dist/build/.) — auto-suggested for known frameworks.
  4. Add environment variables if the build needs them, then Deploy.

Now it's continuous: every push to the default branch → auto build → production deploy; every other branch/PR → its own preview URL; every deploy stays saved, so a bad push is a one-click rollback on the Deploys page.

Rule of thumb: drag-and-drop to try, Git integration to ship — once the repo is connected, deploying just happens. Terminal alternative: npx netlify-cli deploy --prod --dir=demo_site (after npx netlify-cli login).

4Example

The demo_site/ folder in this workspace is a complete static site (one index.html). Deploy it either way:

  • Drop: open app.netlify.com/drop, drag demo_site in → live URL in ~30 seconds (the page says "It's live! 🎉").
  • Git: put demo_site in a GitHub repo → Add new site → pick it → build command: empty, publish directory: . → Deploy → push another commit and watch the second deploy appear on its own.
Requirements
A free Netlify account and internet. No Node, no build step — the folder is the site.

5Advantages

  • Shortest path to a URL anywhere — files in, live site out, no config, no repo, no CLI.
  • Deployment stops being a task — with Git connected, every push is a deploy, with previews and rollbacks built in.
  • Zero server ops — CDN, HTTPS, scaling and patching are the platform's job; you only manage files.

6Conclusion

Netlify has two doors: Drop (drag a folder of finished files → live in under a minute) and Git integration (connect a repo, set build command + publish directory → every push auto-deploys, with branch previews and one-click rollback). The pattern: drop to try, Git to ship.
