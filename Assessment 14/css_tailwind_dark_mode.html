Tailwind CSS: Dark Mode

One variant — dark: — and two triggers. The media strategy follows the user's operating system; the class strategy hands you the toggle. Both, with full implementation steps.

CSS Framework · Tailwind · Dark Mode

1Introduction

Dark mode in Tailwind is a single variant, dark:, that re-declares any utility for dark contexts: bg-gray-50 dark:bg-slate-950, text-gray-900 dark:text-white. The real decision is when "dark" is true — and Tailwind offers two strategies:

  • media (the default) — dark mode follows the user's operating-system preference. Zero JavaScript, zero configuration.
  • class — dark mode is triggered by a .dark class you toggle on <html>. You own the switch, the persistence and the initial state.

Same markup, same dark: utilities — only the trigger differs. Everything below covers both.

2Syntax and its Explanation

The dark: variant

<!-- paired on the same element: light value, then its dark twin -->
<div class="bg-gray-50 dark:bg-slate-950 text-gray-900 dark:text-white">
  <p class="border-gray-200 dark:border-slate-800">…</p>
</div>

It works on any utility — backgrounds, text, borders, shadows, rings, gradient stops — and it composes with every other variant: hover:dark:bg-slate-800, md:dark:px-8. The habit that keeps it readable: keep each pair together on the same element, light value first.

Declaring the strategy

// tailwind.config.js (v3) — 'media' is the default
export default {
  darkMode: 'media',   // follow the OS
  // darkMode: 'class',
  // darkMode: ['class', '[data-theme="dark"]'],  // custom selector
}
/* v4 — CSS. media is the default; opt into class strategy with: */
@import "tailwindcss";
@custom-variant dark (&:where(.dark, .dark *));

The v4 selector reads: "dark means this element, or any descendant of .dark" — and the :where() keeps its specificity at zero, so your own rules still win.

Implementation — media strategy

  1. Do nothing in the config — media is the default in v3 and v4.
  2. Design light-first; add dark: twins only where the light value breaks (surfaces, text, borders, shadows).
  3. Preview it: DevTools → More tools → Render → Emulate CSS prefers-color-scheme — or simply switch your OS theme.

That's the entire implementation. The trade-off: you can't offer a per-site override.

Implementation — class strategy

  1. Set the strategy: darkMode: 'class' (v3) or the @custom-variant line (v4).
  2. Add <meta name="color-scheme" content="light dark"> — native form controls and scrollbars follow the theme, and it prevents a white flash.
  3. Seed the initial state on load: stored choice first; if none, fall back to matchMedia('(prefers-color-scheme: dark)').
  4. Wire the toggle: document.documentElement.classList.toggle('dark') + persist to localStorage.
  5. Pair light/dark values together on the same element as you write — don't hunt for darks later.

Don't manually invert everything. Pick a neutral family that's already dark-friendly (slate, zinc, gray) and add dark: only where the light value breaks. Brand accents usually stay put; what flips is surfaces, text and borders. Images often just need dark:brightness-75 or a separate asset.

4Example Programs with Explanation

Example 1 — Media strategy (runnable, no JavaScript)

The entire feature is a pair of utilities per element. Save as index.html (needs internet) and watch it react to your operating system.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <meta name="color-scheme" content="light dark">
  <title>Dark mode — media strategy</title>
  <script src="https://cdn.tailwindcss.com"></script>
</head>
<body class="bg-gray-50 dark:bg-slate-950 text-gray-900
            dark:text-slate-100 p-6">
  <div class="max-w-md mx-auto mt-8 bg-white dark:bg-slate-900
              border border-gray-200 dark:border-slate-800
              rounded-2xl p-6 shadow-sm">
    <h1 class="text-xl font-bold">Media strategy</h1>
    <p class="mt-2 text-sm text-gray-600 dark:text-slate-400">
      Zero config, zero JavaScript. The dark: variant
      compiles to @media (prefers-color-scheme: dark) —
      your operating system decides.
    </p>
    <ul class="mt-4 space-y-2 text-sm text-gray-700 dark:text-slate-300">
      <li class="bg-gray-100 dark:bg-slate-800 rounded-lg px-3 py-2">Surfaces: gray-50 → slate-950</li>
      <li class="bg-gray-100 dark:bg-slate-800 rounded-lg px-3 py-2">Text: gray-900 → slate-100</li>
      <li class="bg-gray-100 dark:bg-slate-800 rounded-lg px-3 py-2">Borders: gray-200 → slate-800</li>
    </ul>
  </div>
  <p class="text-center mt-6 text-xs text-gray-400 dark:text-slate-500">
    Switch your OS theme, or DevTools → Render →
    "Emulate CSS prefers-color-scheme".
  </p>
</body>
</html>
Explanation of Example 1:
  • No config, no script: dark: utilities compile to @media (prefers-color-scheme: dark), and the OS decides.
  • The color-scheme meta makes scrollbars and form controls follow along for free.
  • Every element keeps its light/dark pair together — surface, then its text, then its border — which is why a dark theme stays readable without a second stylesheet.
How to run
Save as index.html and open in a browser with internet. Toggle your OS between light and dark, or in DevTools: More tools → Render → Emulate CSS prefers-color-scheme. Nothing on the page knows JavaScript exists.

Example 2 — Class strategy: toggle + persistence

The product version: a user-controlled switch, remembered between visits, seeded from the system preference on first visit. Save as index.html (needs internet).

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <meta name="color-scheme" content="light dark">
  <title>Dark mode — class strategy</title>
  <script src="https://cdn.tailwindcss.com"></script>
  <script>
    tailwind.config = { darkMode: 'class' }
  </script>
</head>
<body class="bg-gray-50 dark:bg-slate-950 text-gray-900
            dark:text-slate-100 p-6">
  <div class="max-w-md mx-auto mt-8 bg-white dark:bg-slate-900
              border border-gray-200 dark:border-slate-800
              rounded-2xl p-6 shadow-sm">
    <div class="flex items-center justify-between">
      <h1 class="text-xl font-bold">Class strategy</h1>
      <button id="toggle"
              class="rounded-lg border border-gray-300 dark:border-slate-700
                     px-3 py-1.5 text-sm font-medium
                     hover:bg-gray-100 dark:hover:bg-slate-800">
        Toggle
      </button>
    </div>
    <p class="mt-2 text-sm text-gray-600 dark:text-slate-400">
      The dark: variant now keys off a
      .dark class on <html> — you decide
      when it is true.
    </p>
  </div>
  <script>
    const root = document.documentElement
    const stored = localStorage.getItem('theme')
    if (stored === 'dark' ||
        (!stored && matchMedia('(prefers-color-scheme: dark)').matches)) {
      root.classList.add('dark')
    }
    document.getElementById('toggle').addEventListener('click', () => {
      root.classList.toggle('dark')
      localStorage.setItem('theme',
        root.classList.contains('dark') ? 'dark' : 'light')
    })
  </script>
</body>
</html>
Explanation of Example 2:
  • tailwind.config = { darkMode: 'class' } flips the variant from a media query to a .dark ancestor — the markup doesn't change at all.
  • The seed block runs on load: a stored choice wins; otherwise the system preference sets the first paint. In a real app this snippet goes in <head>, before the body renders, to avoid a flash.
  • The toggle is two lines: classList.toggle('dark') + localStorage.setItem. Fifteen lines of JavaScript is the entire dark-mode feature.
  • Because the variant is an ancestor selector, one class on <html> themes the whole document — no per-element JavaScript.
How to run
Save as index.html and open in a browser with internet. Click Toggle, then reload: the choice survives. Clear site data and reload: it falls back to your OS preference.

5Advantages

  • One variant, total coverage: dark: works on every utility and composes with hover:, md:, group- — a full theme is just pairs of classes.
  • No second stylesheet: there's no dark.css to keep in sync — the twins live next to the values they replace.
  • media strategy is free accessibility: respecting the user's OS preference is the default behavior, zero JavaScript.
  • class strategy is ~15 lines of JS for a toggle with persistence — cheaper than most third-party theme libraries.
  • Both survive v4: media stays the default; the class strategy is one @custom-variant line.

6Conclusion

Dark mode in Tailwind is a variant, not a framework: dark: re-declares any utility, and the strategy decides the trigger. media compiles to a prefers-color-scheme media query — zero code, follows the OS. class keys off .dark on <html> — a toggle, localStorage, and a system-preference seed, fifteen lines total.

Choose media when the site should simply respect the user; choose class when the product needs its own switch — and in either case, write the pairs together: light value, dark twin, same element, every time.
