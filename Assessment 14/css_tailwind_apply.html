Tailwind CSS: The @apply Directive

When the same dozen utilities repeat on forty buttons, @apply inlines them into one class — what it is, how to use it for reusable component classes, and where it quietly stops being a good idea.

CSS Framework · Tailwind · @apply

1Introduction

Tailwind's rule is to write utilities in your markup. The exception is when the exact same combination repeats — a button you've written forty times. The @apply directive takes a list of utilities and inlines their CSS into your own class, so the definition lives once in a stylesheet and the markup just says class="btn". 

/* components.css — the whole definition */
.btn {
  @apply bg-blue-600 hover:bg-blue-700 text-white
         font-semibold px-4 py-2 rounded-lg transition;
}

One important qualification up front: @apply is a build-time directive. Your PostCSS build compiles it; a plain <style> tag does nothing with it. The Play CDN supports it only inside a <style type="text/tailwindcss"> block — which both examples in Section 4 use, so they still run by opening a file.

2Syntax and its Explanation

The basic form

.selector { @apply utility utility …; } — the output is the utilities' declarations, inlined into that selector.

/* what the build emits (simplified) */
.btn {
  background-color: #2563eb;
  color: #fff;
  font-weight: 600;
  padding: .5rem 1rem;
  border-radius: .5rem;
  transition-property: color, background-color, border-color,
                       box-shadow, transform;
}
.btn:hover { background-color: #1d4ed8; }

Read the :hover line: variants listed in the @apply become real selectors in the output.

Variants and responsive prefixes work inside

/* a variant → a nested selector */
.nav-link { @apply text-sm text-gray-600 hover:text-blue-600; }

/* a responsive prefix → a media query */
.shell { @apply max-w-7xl mx-auto px-4 md:px-6; }

One class can therefore hold a component's entire lifecycle — base look, hover, focus ring, and mobile vs desktop padding — while the markup stays two words.

Put it in @layer components

@layer components {
  .btn { @apply …; }
}

Layers set the order: base → components → utilities. Placing the class in components means a utility on the same element still wins — class="btn bg-red-600" re-skins the button without touching any CSS. That layering is what keeps @apply from becoming a trap: there is always an escape hatch in the markup.

The Play CDN form

<script src="https://cdn.tailwindcss.com"></script>
<style type="text/tailwindcss">
  .btn { @apply bg-blue-600 text-white px-4 py-2 rounded-lg; }
</style>

The type="text/tailwindcss" tag tells the CDN to run its in-browser compiler on the block — the only way to use @apply without a local build.

Tailwind v4: @apply still works with the same syntax. The new recommendation is to define reusable things with @utility — e.g. @utility btn { @apply …; } — because @utility-registered names are first-class: they accept variants and can themselves be @applyed. Plain .class + @apply remains fine for internal component styles.

3Features & Uses

Where @apply earns its keep

SituationVerdict
Repeated components (button, input, card) — the same classes in many places@apply — change it once, it updates everywhere
Accessibility wrappers (.skip-link, .sr-only helpers)@apply — behavior-level, used often, rarely read
Base-layer element styling (body font, heading rhythm)@apply or plain CSS in @layer base
Porting an existing design's component CSS into a Tailwind project@apply — translates old class names to the token scale

When to avoid it

  • One-off styles. If the combination appears once, write it in the markup — @apply buys indirection with zero reuse.
  • Runtime variation. @apply bakes values in at build time. Per-instance colors or sizes belong in CSS custom properties + arbitrary values (bg-[var(--c)]), not in a family of @applyed classes.
  • Over-abstraction. A .card that encodes layout + color + state + spacing is a second component framework, now fighting Tailwind instead of using it. Component classes should be small.
  • Deep chains. A class that @applys another custom class that @applys a third is a maze the moment something breaks. Keep it one level deep.
  • Things that must stay greppable. If the team needs to find every place a focus ring is applied, utilities in markup are searchable; @applyed ones are not.
Rule of thumb: utilities in markup by default. Reach for @apply when the exact same classes repeat 3+ times, or when the class is a behavior (skip link, sr-only wrapper) rather than a look. When in doubt — utilities.

4Example Programs with Explanation

Example 1 — Component classes with @apply

A sign-in form whose buttons and inputs are @applyed component classes. The <style type="text/tailwindcss"> block is the entire stylesheet. Save as index.html (needs internet).

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>@apply — component classes</title>
  <script src="https://cdn.tailwindcss.com"></script>
  <style type="text/tailwindcss">
    @layer components {
      .btn {
        @apply inline-flex items-center gap-2 rounded-lg px-4 py-2
               text-sm font-semibold transition;
      }
      .btn-primary { @apply bg-blue-600 text-white hover:bg-blue-700; }
      .btn-ghost   { @apply bg-transparent text-gray-700 hover:bg-gray-100; }
      .input {
        @apply w-full rounded-lg border border-gray-300 px-3 py-2 text-sm
               focus:outline-none focus:ring-2 focus:ring-blue-500;
      }
    }
  </style>
</head>
<body class="bg-gray-50 p-6 text-gray-900">
  <form class="max-w-sm mx-auto mt-8 bg-white border border-gray-200
               rounded-2xl p-6 shadow-sm">
    <h1 class="text-lg font-bold">Sign in</h1>
    <label class="mt-4 block text-sm font-medium">Email</label>
    <input class="input mt-1" type="email" placeholder="[email protected]">
    <label class="mt-4 block text-sm font-medium">Password</label>
    <input class="input mt-1" type="password" placeholder="••••••••">
    <div class="mt-6 flex gap-3">
      <button class="btn btn-primary">Sign in</button>
      <button class="btn btn-ghost">Cancel</button>
    </div>
  </form>
</body>
</html>
Explanation of Example 1:
  • The type="text/tailwindcss" block is compiled by the CDN — this is the browser-only form of @apply.
  • .btn-primary { @apply bg-blue-600 hover:bg-blue-700; } compiles to a real .btn-primary:hover rule — variants included.
  • Both buttons share the .btn base and add only their colors — component classes compose in the markup the way utilities do.
  • .input's focus:ring-2 shows the payoff: the accessibility focus state is one token away, using the same ring scale the rest of the app uses.
How to run
Save as index.html and open in a browser with internet. Change .btn-primary's bg-blue-600 to bg-emerald-600 and refresh: every primary button in the app re-skins from one line.

Example 2 — Responsive @apply, and the anti-pattern

A shell and a card that are worth abstracting (used on every page), next to a hero class that isn't — the same page shows both sides of the rule.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>@apply — responsive + limits</title>
  <script src="https://cdn.tailwindcss.com"></script>
  <style type="text/tailwindcss">
    /* good: a layout shell — the same responsive classes on 6+ pages */
    .shell { @apply max-w-7xl mx-auto px-4 md:px-6 lg:px-8; }
    /* good: a card base used everywhere */
    .card { @apply bg-white border border-gray-200 rounded-2xl shadow-sm p-6; }
    /* AVOID: layout + color + state baked into one class is a second
       component framework. The page below does the hero in utilities. */
    .hero-marketing {
      @apply bg-gradient-to-r from-blue-600 to-indigo-600 text-white
             rounded-3xl p-10 md:p-16 flex flex-col items-center text-center;
    }
  </style>
</head>
<body class="bg-gray-50 text-gray-900">
  <div class="shell py-8">
    <!-- the anti-pattern class exists above, but this page does the right thing -->
    <section class="bg-gradient-to-r from-blue-600 to-indigo-600 text-white
                    rounded-3xl p-10 md:p-16 flex flex-col items-center
                    text-center">
      <h1 class="text-3xl md:text-4xl font-bold">Hero, in utilities</h1>
      <p class="mt-3 text-blue-100 max-w-md text-sm">
        One-off design? Keep it in the markup — no indirection,
        fully greppable.
      </p>
    </section>
    <div class="mt-6 grid gap-4 md:grid-cols-3">
      <div class="card"><h3 class="font-semibold">Card 1</h3><p class="mt-1 text-sm text-gray-500">.card from @apply.</p></div>
      <div class="card"><h3 class="font-semibold">Card 2</h3><p class="mt-1 text-sm text-gray-500">Change it once, updates everywhere.</p></div>
      <div class="card"><h3 class="font-semibold">Card 3</h3><p class="mt-1 text-sm text-gray-500">A utility in markup still wins over .card.</p></div>
    </div>
  </div>
</body>
</html>
Explanation of Example 2:
  • .shell { @apply max-w-7xl mx-auto px-4 md:px-6 lg:px-8; } — responsive prefixes compile to media queries inside the class, so the layout rhythm lives in one place.
  • .card is a legitimate @apply target: the same six utilities on every card in the app.
  • .hero-marketing is defined but not used — the hero is written in utilities in the markup instead. Layout + color + state in one class means every variation forks the class; one-off design belongs in the markup, where it's greppable.
  • Because the @applyed classes sit in @layer components, class="card bg-red-50" would override its background — the utilities layer still wins.
How to run
Save as index.html and open in a browser with internet. Resize below 768px and watch .shell's padding step from px-4 to md:px-6. Then delete the unused .hero-marketing block — nothing changes, which is the point.

5Advantages (and the honest costs)

  • DRY where it's real: change .btn once and forty buttons update; the definition is a single greppable line.
  • Token-based by construction: @applyed values come from the scale, so brand changes stay centralized — no hex codes drifting into CSS.
  • Variants and responsiveness work: hover:, focus:, md: all compile correctly into the component class.
  • Markup stays calm: a form of five @applyed controls reads like semantics, not class soup.
  • Override-safe by layering: in @layer components, a markup utility still wins — the escape hatch is always one class away.
  • The costs, honestly: indirection (markup no longer says what things look like), a build requirement, and the temptation to over-abstract. Those are discipline costs, not technical ones.

6Conclusion

@apply is the bridge between Tailwind's utility-first core and ordinary component CSS: it inlines utilities into your own classes at build time, with variants, responsive prefixes and layering all working. It shines on the things that truly repeat — buttons, inputs, shells, accessibility wrappers — and it goes stale the moment a style is one-off, varies at runtime, or swallows a whole design.

The working rule: utilities in markup by default; @apply when the same classes repeat 3+ times; and component classes stay small enough that you could still read them at a glance.
