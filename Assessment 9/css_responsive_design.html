Responsive Design: Media Queries, Breakpoints & Container Queries

What responsive design is, how mobile-first media queries and breakpoints work, and how container queries let components respond to their container — with a side-by-side comparison.

CSS · Responsive · Media & Container Queries

1Introduction

Responsive design means building one website that looks good and works well on every screen size — phones, tablets, laptops, and large desktops — instead of building a separate site for each device. The layout fluidly adapts: columns stack on a phone, sit side by side on a tablet, and spread out on a desktop.

The idea was coined by Ethan Marcotte (2010) and rests on three ingredients:

  • Fluid grids — layouts sized in flexible units (%, fr) instead of fixed pixels.
  • Flexible images — images that shrink to fit their container (max-width: 100%).
  • Media queries — CSS rules that apply only when the screen meets a condition (e.g. wider than 768px).

Modern best practice is mobile-first: write the base styles for the smallest screen, then add enhancements for larger screens with min-width media queries. And the newest evolution, container queries, lets a component respond to the width of its own container rather than the whole screen — perfect for reusable cards and widgets.

2Syntax and its Explanation

Step 0 — the viewport meta tag (required)

Without this tag, phones render the page at desktop width and zoom out. Every responsive page needs it in the <head>:

<meta name="viewport" content="width=device-width, initial-scale=1.0">

Media query syntax

/* Base (mobile) styles first */
.cards { display: grid; grid-template-columns: 1fr; }

/* At 600px and wider, switch to 2 columns */
@media (min-width: 600px) {
  .cards { grid-template-columns: 1fr 1fr; }
}

A media query has two parts: the @media rule with a condition in parentheses (most often min-width or max-width), and a block of styles that apply only when the condition is true. The widths where the layout changes are called breakpoints.

Container query syntax

Container queries need two steps: first declare a parent as a container with container-type, then query it with @container:

/* Step 1: mark the parent as a container (width-queryable) */
.box { container-type: inline-size; }

/* Step 2: when THAT box (not the screen) is 380px+, lay the card out horizontally */
@container (min-width: 380px) {
  .card { flex-direction: row; }
}
container-type valueMeaning
normalDefault — not a query container.
inline-sizeQueryable by width — the one you want 99% of the time.
sizeQueryable by width and height — but the element can no longer size itself from its content, so use with care.

You can also name a container (container-name: sidebar) and target it explicitly: @container sidebar (min-width: 400px) { … }. Without a name, @container uses the nearest container ancestor.

Key rule: Media queries ask "how wide is the screen?" while container queries ask "how wide is my parent box?" — and the golden rule of breakpoints is: choose them where your content breaks, not by device names.

3Features & Uses

1. Mobile-first media queries

Write the phone layout as plain CSS, then layer min-width queries on top. Each query only adds or overrides what the bigger screen needs — small, fast CSS for phones, richer layouts for desktops.

/* Phone: stacked */
.layout { display: grid; gap: 12px; }
/* Tablet and up: sidebar + content */
@media (min-width: 768px) {
  .layout { grid-template-columns: 220px 1fr; }
}

2. Breakpoints — let the content decide

There are no magic numbers: slowly narrow your browser until the layout looks cramped — that width is your breakpoint. Still, most projects settle near 600px, 900px, and 1200px, which cover phones, tablets, and desktops nicely.

@media (min-width: 600px)  { /* tablet */ }
@media (min-width: 900px)  { /* laptop */ }
@media (min-width: 1200px) { /* desktop */ }

3. Fluid grids & flexible images

Breakpoints handle big changes; fluid units handle everything in between. auto-fit + minmax() makes a grid that adds or removes columns automatically, and one image rule prevents overflow everywhere.

.gallery { display: grid;
  grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)); }
img { max-width: 100%; height: auto; }

4. Container queries — components that adapt anywhere

The classic problem: the same card component appears in a wide main column and a narrow sidebar. A media query can't help — the screen is identical in both cases. A container query can: each card adapts to its own box.

.box { container-type: inline-size; container-name: cardbox; }
@container cardbox (min-width: 380px) {
  .card { flex-direction: row; }
}

4Example Programs with Explanation

Example 1 — Mobile-first cards with breakpoints

This page shows three cards that stack in 1 column on phones, switch to 2 columns at 600px, and 3 columns at 900px — pure mobile-first min-width queries.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <style>
    /* MOBILE FIRST: 1 column by default */
    .cards { display: grid; grid-template-columns: 1fr; gap: 12px; }
    .cards > div { background: #2563eb; color: white;
      padding: 18px; border-radius: 8px; text-align: center; }

    /* TABLET: 2 columns at 600px and up */
    @media (min-width: 600px) {
      .cards { grid-template-columns: 1fr 1fr; }
    }

    /* DESKTOP: 3 columns at 900px and up */
    @media (min-width: 900px) {
      .cards { grid-template-columns: 1fr 1fr 1fr; }
    }
  </style>
</head>
<body>
  <div class="cards">
    <div>Card 1</div><div>Card 2</div><div>Card 3</div>
  </div>
</body>
</html>
Explanation of Example 1:
  • The viewport <meta> tag lets phones report their true width.
  • Base styles target mobile: a single-column grid — no query needed.
  • @media (min-width: 600px) adds a second column for tablets and everything larger.
  • @media (min-width: 900px) adds a third column for laptops/desktops.
  • Because queries use min-width, wider screens inherit all the smaller breakpoints' rules — the essence of mobile-first.

Example 2 — A container-query profile card

The same profile card is placed in a narrow (250px) box and a wide box. With zero media queries, each instance adapts to its own container: stacked in the narrow box, horizontal in the wide one.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <style>
    /* Step 1: each wrapper becomes a query container */
    .box { container-type: inline-size;
      border: 1px dashed #2563eb; padding: 12px; margin-bottom: 16px; }
    .narrow { width: 250px; }

    /* Card stacks vertically by default */
    .card { display: flex; flex-direction: column; gap: 10px;
      background: #eff6ff; padding: 14px; border-radius: 8px; }

    /* Step 2: when the CONTAINER (not the screen) reaches 380px, go horizontal */
    @container (min-width: 380px) {
      .card { flex-direction: row; align-items: center; }
    }
  </style>
</head>
<body>
  <div class="box narrow">
    <div class="card">… stacked card …</div>
  </div>
  <div class="box">
    <div class="card">… horizontal card …</div>
  </div>
</body>
</html>
Explanation of Example 2:
  • container-type: inline-size turns each .box into a width-queryable container.
  • The card's default CSS stacks it vertically — this is what the narrow 250px box shows.
  • @container (min-width: 380px) fires per-box: only the wide box qualifies, so only that card turns horizontal.
  • No media query is involved — both cards render differently on the same screen at the same time.
How to try it
Copy either example into a file named index.html and open it in a browser. For Example 1, resize the window across 600px and 900px to watch the columns change. For Example 2, try changing 250px to 450px and watch the "narrow" card flip horizontal — no screen resize needed.

5Advantages

  • One site for every device: A single codebase serves phones, tablets, and desktops — no separate "mobile site" to maintain.
  • Better user experience: Content is always readable and tappable without pinching, zooming, or sideways scrolling.
  • SEO-friendly: Search engines (Google indexes mobile-first) reward mobile-friendly pages with better rankings.
  • Mobile-first is faster: Phones download lean base styles first and only add enhancements larger screens need.
  • Truly reusable components: Container queries let one card or widget adapt to a sidebar, a modal, or full width with no extra classes.
  • Future-proof: Content-based breakpoints and container-relative components keep working as new device sizes appear.

6Conclusion

Responsive design is the practice of making one website adapt gracefully to any screen, built on fluid grids, flexible images, and queries. Mobile-first media queries with min-width breakpoints shape the page skeleton — phone layout by default, enhancements layered on — while container queries let individual components respond to their own box instead of the screen.

In summary: use media queries for the page, container queries for the parts, and always pick breakpoints where your content breaks — not by device name. Master these, and your layouts will look intentional everywhere. As the saying goes: "Content is like water — design the glass, and let it take its shape."
