CSS Specificity, Cascade & Inheritance

Understanding how the browser decides which CSS rule wins when there's a conflict — with examples.

CSS · Resolution · Conflict

1Introduction

When you write CSS, it's very common for more than one rule to try to style the same element. For example, a paragraph might be styled by p, by a class like .note, and by a specific id. So how does the browser know which one to use? This is the job of the cascade.

Three key ideas work together to settle any conflict:

  • Cascade — the process by which the browser combines all the (possibly conflicting) declarations that apply to an element, and decides the final value. It's the "waterfall" of rules.
  • Specificity — a way of assigning a "weight" to each selector. The more specific a selector is, the more it wins. Generally, id > class/attribute > element.
  • Inheritance — some CSS properties (like color and font-family) are passed down from a parent element to its children, so you don't have to repeat them.

In short: inheritance helps values flow down the tree, specificity helps pick a winner among competing rules, and the cascade is the overall decision process that combines them.

2Syntax and its Explanation

How specificity is calculated

Specificity is usually expressed as three numbers: (a, b, c). You can think of it like a score where:

LevelCounts asExamples
ID1 point in the id column#header
Class / Attribute / Pseudo-class1 point in the class column.box, [type="email"], :hover
Element / Pseudo-element1 point in the element columnp, div, ::before
p            // specificity (0,0,1)
.note         // specificity (0,1,0)
#main         // specificity (1,0,0)
p.note        // specificity (0,1,1)
#main p.note  // specificity (1,1,1) — the highest here

Inheritance

Text-related properties (color, font, line-height, text-align) are inherited by children. Box properties (margin, padding, border, width) are not inherited by default.

/* The p inherits color from its parent (e.g. a div) */
div { color: red; }
div p { /* p still red unless you override it */ }
Key rule: To resolve a conflict, the browser compares specificity first. If specificities are equal, the rule that comes later in the stylesheet (or the one with !important) wins. Inheritance only provides the "default" when there's no direct rule at all.

3Features & Uses

1. Specificity — who wins a direct conflict

A more specific selector overrides a less specific one. This is why an inline style and !important are so powerful — and why they're generally avoided.

p    { color: gray; }     // (0,0,1) loses
.note { color: red; }      // (0,1,0) wins
#main { color: blue; }     // (1,0,0) wins over both

2. Order matters — when specificity is equal

If two rules have the same specificity, the one that appears later in the CSS file wins. This is why the order of your rules can change the result.

p  { color: blue; }   // first
p  { color: red; }    // later — wins

3. !important — the trump card (used carefully)

A declaration with !important overrides normal declarations, regardless of specificity. Use it sparingly, as it makes the cascade hard to reason about.

#main p { color: blue !important; }
p.note { color: red; }   // loses to !important above

4. Inheritance — property values flow down

Setting a property like color on a parent automatically applies to all its children and grandchildren. This is what makes big style blocks possible.

body { color: #333; }   // everything inherits this
h1   { font-family: Arial; }  // h1 and its children get Arial

5. Inherited vs. non-inherited properties

// Inherited by default:
color, font-family, font-size, line-height, text-align

// NOT inherited by default:
margin, padding, border, width, height
Did you know? A good habit is to keep selectors low-specificity (prefer classes over ids), write rules in a sensible order, and only reach for !important as a last resort. This keeps your CSS predictable and easy to override later.

4Example Programs with Explanation

Example 1 — How the browser resolves conflicting rules

This example lays out several conflicting rules for the same element and shows which one wins by specificity and by order. Change the rules to see the browser behave differently.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <style>
    /* 1. Element selector — low specificity (0,0,1) */
    p { color: gray; }

    /* 2. Class selector — higher (0,1,0), so it beats the p */
    .note { color: red; }

    /* 3. ID selector — highest (1,0,0), beats both */
    #special { color: blue; }

    /* 4. Same specificity as 1, but LATER: this wins the tie */
    body p { color: green; }  // (0,0,2) — beats plain p
  </style>
</head>
<body>
  <p class="note" id="special">
    Which color wins? The ID selector (#special) has the highest
    specificity, so this text should be blue.
  </p>
</body>
</html>
Explanation of Example 1:
  • Several rules target the same paragraph, so the browser must cascade to pick one.
  • p (0,0,1) is the weakest; .note (0,1,0) beats it; #special (1,0,0) beats both.
  • body p (0,0,2) has more element points than a plain p, so it beats the plain p too.
  • Because the ID selector has the highest specificity, the paragraph ends up blue.

Example 2 — Inheritance flowing down the tree

This example shows how text properties inherited from a parent cascade to children, and how a child can override them. The box properties (margin/padding) are not inherited, which is why each box has its own spacing.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <style>
    /* Parent: sets color & font — children will END UP INHERITING these */
    section {
      color: #0f766e;
      font-family: Georgia, serif;
      border: 2px solid #ccc;   // border is NOT inherited
      padding: 10px;               // padding is NOT inherited
    }

    /* Child: overrides color (a child can always ignore inheritance) */
    section p { color: #b91c1c; }
  </style>
</head>
<body>
  <section>
    This section is teal, in Georgia.
    <p>But this paragraph overrides the color to red,
    while still inheriting the Georgia font and its own padding.</p>
    <span>This span inherits teal and Georgia too.</span>
  </section>
</body>
</html>
Explanation of Example 2:
  • The section's color and font-family are inherited by the p and span children.
  • The child p overrides the color to red via its own rule (you can always override inherited values).
  • border and padding on the section are not inherited — the paragraph gets its own default (no border).
  • This is a clean example of inheritance flowing down and a child taking control when needed.
How to try it
Copy either example into a file named index.html and open it in a browser. In Example 1, try pausing #special to see the class's red win; in Example 2, remove the section p rule to see the paragraph inherit the parent's teal.

5Advantages

  • Predictable styling: Understanding the cascade lets you confidently override styles.
  • Less repetition: Inheritance means you don't restate color or font on every child.
  • Cleaner code: Using classes (low specificity) keeps your CSS easy to maintain and extend.
  • Scalability: A clear specificity strategy makes large stylesheets manageable.
  • Powerful control: When you need it, specific selectors and the cascade can target precisely.
  • Easier debugging: Knowing why a rule wins helps you fix "why isn't my style applying?" quickly.

6Conclusion

The cascade, specificity, and inheritance are the rules that let CSS resolve conflicts. Inheritance passes values down the document tree. Specificity grades each selector (id beats class beats element). And the cascade is the overall process that, considering specificity, source order, and !important, settles on the final value for every property.

In summary: when two rules conflict, compare specificity first; if equal, the later one wins; !important trumps both; and inherited values only apply when no direct rule exists. Master these three ideas, and you'll be able to predict — and control — exactly how your page is styled. As the saying goes: "The cascade is the art of choosing, and inheritance is the art of sharing."
