Markdown Syntax

The complete everyday set — headings, emphasis, lists, inline and fenced code, tables, links and images — each shown as source and as the rendered result.

Documentation · Markdown

1Introduction

Markdown is a lightweight markup language: you write plain text with a small set of symbols, and a renderer turns it into a formatted document (HTML). Created in 2004 by John Gruber, it's now the default format for README files, issue trackers, technical docs, notes apps and chat tools — because it's readable unrendered: a raw .md file makes sense even before anything converts it.

The philosophy in one line: formatting should be a side effect of plain text, not a battle with a word processor. A paragraph is just lines separated by a blank line; a heading is a line that starts with #. No tags, no escaping, no cursor-hunting for a menu. 

# the whole "document" model of Markdown
plain text lines        →  paragraphs
# symbol + text         →  heading
- symbol + text         →  list item
`backticks`             →  inline code
[text](url)             →  link
![alt](url)             →  image
| a | b |               →  table cell

2Syntax and its Explanation

Headings — # through ######

One to six # at the start of a line, then a space, then the text. The number of hashes sets the level.

# Chapter title            <h1>
## Section                 <h2>
### Subsection             <h3>
#### Down to ###### h6

Chapter title

Section

Subsection

Habit: a document has one #, and levels shouldn't skip (## → ###, not ## → ####). Renderers and TOC generators both rely on the structure.

Emphasis — italic, bold, both, strikethrough

*italic*      or   _italic_
**bold**      or   __bold__
***bold italic***
~~strikethrough~~   (GitHub/Flavored Markdown)

italic · bold · bold italic · strikethrough

Lists — unordered, ordered, nested

<!-- unordered: - (or * or +), nested with 2-space indents -->
- Apples
- Oranges
  - Navel
  - Blood

<!-- ordered: numbers + dot (the numbers you type don't matter) -->
1. Boil water
1. Steep for 3 minutes
1. Strain

<!-- task lists (GitHub/Flavored Markdown) -->
- [x] Write the docs
- [ ] Ship it
  • Apples
  • Oranges
    • Navel
    • Blood
  1. Boil water
  2. Steep for 3 minutes
  3. Strain
  • Write the docs
  • Ship it

Code — inline and fenced blocks

Inline code goes in single backticks — great for file names, commands, class names. Multi-line code goes in a fenced block: three backticks on a line by themselves, optionally followed by a language name for syntax highlighting.

Run `npm install` and then `npm run dev`.

```js
function greet(name) {
  return `Hello, ${name}!`;
}
```

The closing fence goes on its own line, left-aligned. (If your code itself contains backticks, use double backticks.)

Tables

| Command   | Purpose          |
| --------- | ---------------- |
| `git add` | stage changes    |
| `git log` | show history     |
CommandPurpose
git addstage changes
git logshow history

The second row of dashes is required — it also sets alignment: :--- left, :---: center, ---: right. Cells can contain emphasis and inline code.

Links

<!-- inline: visible text, then URL in parens -->
[GitHub](https://github.com)

<!-- autolink: bare URLs just work (Flavored Markdown) -->
https://example.com

<!-- reference style: short in text, URL defined once below -->
See the [spec][md].

[md]: https://daringfireball.net/projects/markdown/

GitHub · https://example.com · See the spec.

Reference style is handy for repeated links — the URL lives in one place you can fix once. A space before the URL inside the parentheses is allowed in Flavored Markdown.

Images

![A friendly cat](images/cat.jpg)

<!-- link an image: wrap it in a link -->
[![A friendly cat](images/cat.jpg)](https://example.com/cats)

— same shape as a link, with an ! in front and alt text that describes it.

Two rules that matter: always write meaningful alt text (screen readers, and the fallback when the image fails to load), and keep image files in a predictable folder (or use a stable URL).

Beyond the basics: blockquotes (> quoted text), horizontal rules (--- on its own line), and reference-style links are part of the core spec. Task lists, strikethrough, autolinks and tables are GitHub Flavored Markdown (GFM) extensions — the dialect you'll meet most often (GitHub, GitLab, VS Code preview, Obsidian).

Where you'll meet Markdown

PlaceWhat it's for
GitHub / GitLab / BitbucketREADME.md, issues, PR descriptions, wikis
VS Code, Obsidian, Notion, Typoranotes and docs with live preview
Slack / Discord (subsets)formatted chat: **bold**, `code`, > quotes
npm / PyPI packagesthe README.md is the package's landing page
Academic & internal docsCHANGELOGs, RFCs, meeting notes — version-controllable text
Why plain text wins: a Markdown file renders in a browser, reads fine in an email, diffs cleanly in Git, survives a copy-paste, and won't be orphaned by a software upgrade. That's why the whole ecosystem standardized on it instead of Word docs.

Example 1 — The core elements in a notes file

Headings, emphasis, both list kinds and inline code — the set that covers 90% of daily writing.

# Weekly Notes — Sprint 14

## What got done
- Shipped the **billing fix** (the *urgent* one)
- Wrote the on-call handover
  - Included the `~/.env` checklist
  - Added the rollback steps

## Next week
1. Review PRs from the frontend team
1. Pair on the search performance work
1. ~~Rewrite the dashboard~~ Just profile it first

> Rule for this sprint: **no feature without a rollback plan.**

The deploy command is `deploy --env prod` — ask Priya for access.
Explanation of Example 1:
  • One # for the document title, ## for sections — a structure any TOC generator can read.
  • The nested unordered list uses 2-space indents; the ordered list reuses 1. for every line (renderers number them automatically).
  • ~~Rewrite the dashboard~~ shows a cancelled plan — the classic strikethrough use in planning docs.
  • > blockquote sets the rule apart; backticks mark the exact command so it's copy-paste-safe.
How to run
Open example1_markdown_basics.md (in this workspace) in VS Code and press Ctrl+Shift+V, or paste it into any Markdown editor's preview.

5Advantages

  • Readable unrendered: the source is the document — in a diff, in an email, in a terminal. No format is more portable than plain text.
  • Minimal to learn: the core set above is learnable in an afternoon; the rest (GFM extensions) is picked up as needed.
  • Version-control friendly: text diffs cleanly in Git, so docs change through the same pull-request flow as code.
  • Renderer-agnostic: the same file renders on GitHub, VS Code, Obsidian, Slack — write once, no export step.
  • Structure without ceremony: headings give documents a table of contents; lists and tables give them scannability — with zero formatting tooling.
  • Extensible where needed: fenced blocks carry real code with highlighting; front-matter (YAML) and plugins add metadata, math and diagrams on top of the same core.

6Conclusion

Markdown is a deliberately small language: # for headings, */** for emphasis, - and 1. for lists, backticks for code (inline and fenced), pipes for tables, [text](url) for links, and ![alt](url) for images. Add GFM's task lists, strikethrough and autolinks, and that's the dialect the entire software industry actually uses.

Its power isn't the formatting — it's that plain text survives everything: Git, email, terminals, and twenty years of software. If you remember one thing, make it the pairing: writable by hand, readable by humans, renderable by machines.
